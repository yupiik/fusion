# Fusion :: AI Skills (`fusion-ai-skills`)

Installable AI coding agent skills (opencode, Claude) for Fusion, distributed as a self-contained CLI.

This module produces installable AI coding agent skills (opencode, Claude Code) AND a self-contained CLI to
install them. It is the distribution vehicle for the skills that teach agents how the whole Fusion project
works (annotation processing, triad, conventions).

## Source of truth for skills

Two kinds of skills are bundled:

- Cross-cutting "concept" skills (project setup, annotation processing, cli, documentation, testing) live as
  hand-authored files in `fusion-build-internal/src/main/resources/agents/skills/<name>/SKILL.md`. A build
  copies each into `fusion-ai-skills/src/main/resources/skills/<name>/SKILL.md`.
- One skill per runtime module (json, http-server, jsonrpc, httpclient, kubernetes-client,
  kubernetes-operator-base, persistence, tracing, handlebars, jwt) is GENERATED by `AgentsFileSynchronizer`
  from `agents/skills/module/SKILL.md`, wrapping the module's own `agents/module/<artifactId>.md` guide (passed
  as the unescaped `guide` variable). The curated module id list lives in the `moduleSkillArtifacts` set in
  that synchronizer.

Generated copies are committed so the published jar is self-contained; edit the template, never the committed
copy. Regenerate with `mvn install -pl fusion-build-internal`. `fusion-runtime-models` was retired in favour of
the per-module skills.

## The install CLI

Two `@Command` Runnable beans under `io.yupiik.fusion.ai.skill.install` copy/remove the bundled skills into
the target agent skill directory:

- `InstallSkillCommand` (`install`)
- `DeleteSkillCommand` (`delete`)

Each takes a `@RootConfiguration("-")` record: `--agent` (opencode | claude | generic, required),
`--scope` (local | global, default `local`), `--target` (explicit path overriding the agent/scope default),
and for `install` a `--force` (default `false`).

Runtime skill resolution must work from a fat jar, so `Skills.bundled()` reads the bundled `skills/` tree
from the classpath directly - on a filesystem or by streaming jar entries. It NEVER extracts to a temporary
directory; do not re-introduce temp-dir extraction.

## Building the executable

`maven-shade-plugin` produces an attached runnable jar with classifier `bin`
(`fusion-ai-skills-<version>-fatjar.jar`) with `Main-Class` = `io.yupiik.fusion.framework.api.main.CliLauncher`
(no shim needed - `CliLauncher.main(String...)` is public). Filter excludes `META-INF/MANIFEST.MF` +
signature files to keep the shade build warning-free.

## Distribution + docs

- Published to Maven Central as `io.yupiik.fusion:fusion-ai-skills`; consumers pull the `-fatjar` classifier jar
  or depend on the plain jar for the bundled skill resources.
- `fusion-documentation` depends on this module and wires `CliDocumentationGenerator` to render the
  `install` command reference into `content/cli/*.adoc`; `fusion/ai-skills.adoc` describes install paths.

## Module rules

- Command parameters must bind and validate via the configuration subsystem; keep the `@Property`
  `documentation` strings rich (they become the browsable CLI reference).
- Always braces on control-flow; ASCII-only docs.



## Working in this module

- Build it: `mvn install -pl fusion-ai-skills -am` (from the repository root).
- The root [AGENTS.md](/AGENTS.md) holds the global rules: reflectionless design, license headers, parallel JUnit 5 tests, ASCII-only.
